# 移动端视频应用交互设计最佳实践调研报告

> **目标读者**：正在重构自建媒体库应用（PC / 网页 / 手机三端，含电影、电视剧、短视频、AV 分类，演员体系，局域网 HTTP 流播放）的开发者。
> **聚焦问题**：手机端看视频的交互体验。
> **方法与范围**：基于公开资料、产品分析与通用 UX 知识总结，不依赖抓取具体站点。内容覆盖 Netflix/Disney+、YouTube/Bilibili、Jellyfin/Emby/Infuse/VidHub、抖音/TikTok 四类产品的移动端交互，并给出对「本地 AV 片库 + 演员体系 + 局域网流播」这一特定场景的可落地启示。
> **核心立场**：媒体库 App 的移动端体验 = **「目录感」浏览（书架/详情）** + **「沉浸感」消费（播放器）** 的组合。Netflix 系代表"详情优先的目录感"，TikTok 系代表"即点即播的沉浸感"。自建媒体库整体应走目录感路线，但在 AV/短视频子域与播放器内部要局部借用沉浸感手势。

---

## 0. 结论先行（TL;DR）

1. **媒体库类 App 移动端有一个共同骨架**：底部 Tab（4~5 个）→ 首页=继续观看 + 分类内容墙 → 点封面进详情 → 播放器全屏 → 返回时收进迷你播放器。这条骨架可直接照搬。
2. **点封面「即播 vs 详情」不是二选一，而是分内容类型**：电影/剧集=详情优先（决策重、信息多）；AV/短视频=即点即播或快速预览（决策轻、封面即内容）。
3. **移动端真正的差异化功夫在"半屏外"**：返回栈怎么处理播放、横竖屏怎么切、锁屏/后台/画中画怎么接管、拇指热区怎么布局——这些 PC/网页端没有，是最值得投入交互设计的地方。
4. **我们项目的两个特色资产**（演员体系、本地局域网流播）恰好对应两个成熟范式：**演员页 ≈ Netflix 的"角色/主创页" + Jellyfin 的 People 页**；**局域网流播 ≈ 无转码、无 DRM 的本地播放器（Infuse 路线）**，交互上可以做普通流媒体做不到的事（后台音频、PiP、关键帧预览）。
5. **AV 子域的特化**：高密度封面网格是主入口、缩略图=决策、隐私（无痕/隐藏记录/防误触）是硬需求；这些在主流产品里有成熟对应（Pornhub 系 + 浏览器的无痕模式），但要在我们自己产品里设计成一等公民，而不是事后加开关。

## 1. Netflix / Disney+ 移动端：内容墙 + 详情优先 + 剧集连播

### 1.1 它们怎么做的

**内容墙信息架构**
- 首页是"横向 Row"堆叠的竖滚动墙：顶部一个大焦点卡（hero），往下是「继续观看」「热门」「按类型/按导演」等一行行可横滑的卡片行。
- 封面比例：电影/剧集用 **2:3 竖版海报卡**（信息密度高、滚动时行高可控），卡片下方标注标题（可选元数据）；「继续观看」行的卡片带 **底部进度条 + 剩余时长**。
- 顶部导航栏在滚动时**下滑隐藏、上滑恢复**，最大化内容可视面积；搜索入口固定（放大镜）。
- 卡片懒加载/占位骨架屏，滚动流畅优先于一次加载全部。

**点封面 → 详情，而不是直接播放**
- 点卡片进入**详情页**（不是播放器）：顶部大横幅背景 + 标题 + 播放/下载按钮 + 简介 + 集列表 + 演员/主创 + 「更多类似」。
- 详情页顶部的 **"Play" 是主 CTA**；Netflix 详情页默认**自动静音播放预览片段**（autoplay preview），用视频动态降低"要不要看"的决策成本，但**不发声、不干扰**，用户滑动即停。
- Netflix 有 **"Play Something"**（随机播放）入口，把"选择困难"问题直接消掉。

**横竖屏处理**
- 浏览/详情固定竖屏；点击播放进入**全屏播放器**，播放器内随设备旋转在横/竖屏间切换（电影内容横屏，竖屏内容是特例）。
- 播放器内旋转是"跟随传感器"而非锁定；从全屏播放返回 = 回到详情页，**播放状态保留**（不重启）。

**剧集连播**
- 一集播完出现 **"下一集倒计时"**（约 10 秒，可取消，可点"立即播放下一集"），是 binge-watching 的核心设计。
- **"跳过片头 Skip Intro" / "跳过回顾 Skip Recap"** 按钮：识别片头/上集回顾，一键跳过。
- Netflix 曾限制连续播放必须"仅 Wi-Fi + 锁定屏幕"（防数据流量与误触耗电），后被取消；这提醒我们：**连播要考虑流量/电量成本**，本地局域网播放则完全不受此限。

**手势（播放器内）**
- 双击屏幕**左右两侧 = 快进/快退 10 秒**；进度条可拖动并**实时显示缩略图预览**。
- 播放/暂停：单击中央。
- 倍速：长按或菜单选择（0.5×~2×）。
- iOS 系统级右滑返回手势贯穿所有页面（包括从播放器返回）。

**"继续观看"行**
- 只要看到一半，条目就进入「继续观看」行，封面带进度条，点一下**从上次位置继续**；看完才消失。

### 1.2 为什么合理

- **Row 内容墙**：订阅制下有海量内容，"浏览发现"的价值高于"精确搜索"，Row 把分类信息横向折叠、把"看什么"的决策成本降到最低；隐藏导航是把每一寸屏给内容。
- **详情优先而不是即播**：电影/剧集是**长决策内容**（要看简介、评分、预告、演职员再决定），详情页是"决策 + 启动"两件事的合并场所；直接播放会误触、会丢失"还没准备好就开播"的挫败感。自动静音预览则是在不打断浏览的前提下把"预告片"喂给用户。
- **连播倒计时**：连续刷剧是这类产品的核心消费模式，倒计时省掉"每集手动点下一集"的摩擦，且给用户 10 秒反悔窗口。
- **双击快进**：比拖进度条快且不易误触，符合"躺着看"的单手场景。

### 1.3 对我们自建媒体库的启示

1. **书架直接照搬 Row 结构但降规模**：本地片库条目数远小于订阅库，不必追求 Netflix 的无限滚动墙；「继续观看」+「按分类/按演员/最近添加」3~5 行即可，空态要好看（第一次打开时引导导入）。
2. **详情页信息中枢**：我们比 Netflix 更需要详情页——因为本地元数据（分辨率/编码/音频格式/文件来源）有"发烧友价值"，且演员体系需要一个展示容器。详情页模板：大封面 + 播放主按钮 + 规格标签 + 简介 + 演员横排 + 相关推荐。
3. **AV 子域反过来**：AV 用户的行为是"扫封面墙 → 快速看 → 换下一个"，决策成本极低。**AV 应默认点封面即播（或点封面弹试看）**，详情页降级为次要路径（长按进详情）。
4. **剧集连播机制原样可用**：本地剧集没有 DRM/版权限制，连播 + 跳过片头（片头时长可本地标记/记忆）是强体验，且我们**无需"仅 Wi-Fi"限制**（本就是局域网）。
5. **进度预览帧**：Netflix 拖进度条有缩略图；本地视频可离线抽关键帧做 seek 预览条，效果甚至更好（局域网传输快）。

## 2. YouTube / Bilibili 移动端：即点即播 + 播放页滚动 + 迷你播放器

### 2.1 它们怎么做的

**竖屏信息流 vs 全屏播放**
- 首页是竖屏卡片流（YouTube 现多为两列网格卡，Bilibili 为两列网格），卡片=封面+标题+作者+时长，**点卡片直接进入播放**，没有"确认详情页"这一跳。
- 播放形态分两档：**半屏（竖屏内嵌播放器 + 下方可滚动的简介/评论/推荐）** 和 **全屏（横屏/竖屏沉浸）**。Bilibili 默认半屏竖页（播放器在顶部，下面滚评论区/弹幕/推荐）；YouTube 默认全屏横屏，也可退半屏。
- 核心区别：**"播放页"本身就是详情页**——信息在播放器下方滚动，而不是单独一页。

**点视频即播的即时性**
- 点即开始加载并播放，**零确认**；点击动作的延迟是"加载进度"而非"页面跳转"。
- 加载阶段：标题 + 旋转 loading，播放器区域先占位，避免布局跳动。

**播放页上下滑动切视频**
- 全屏播放时，**上滑 = 下一个视频，下滑 = 上一个**（队列 = 当前列表/自动推荐）；短视频（Short/Shorts）则是整屏 feed 式上下滑。
- 这个手势把"换内容"的成本降到几乎为零，是沉浸式消费的关键。

**迷你播放器（mini player / PiP）**
- 从播放页返回信息流后，播放器**收缩为右下角悬浮小窗**（可拖动、可点回全屏、可关闭），视频/音频继续播放；再点返回则收起。
- iOS 上 YouTube 用系统 **PiP（画中画）**，切出 App 也能看；Bilibili 用应用内小窗（悬浮窗权限）。
- 价值：**"返回浏览"和"继续观看"不互斥**——边刷别的视频边听/边看。

**进度记忆**
- 自动记住观看位置；再次打开该视频给 **"从上次播放位置继续"** 提示（toast + 按钮）；Bilibili 首页有「继续观看」入口、进度条标注。
- 已看完的视频重置进度；观看历史列表可回溯。

### 2.2 为什么合理

- **即点即播**：UGC/中短视频是"快速消费"内容，决策成本接近零，"播放即页面"省一次跳转；信息密度让"详情页单独存在"不划算，于是详情内容被压进播放页下方滚动。
- **上下滑切视频**：消费是"流式"的，手势切换比"返回列表 → 点下一个"快一个数量级；这也顺应竖屏单手持机的自然滑动。
- **迷你播放器**：解决"看视频与浏览内容"的多任务矛盾，是移动端最被低估的交互之一；它把"播放"从页面状态提升为**全局状态**。
- **进度记忆**：长视频时间成本高，尊重用户的离开/返回是基本礼貌；对"看了一半明天继续"的场景是刚需。

### 2.3 对我们自建媒体库的启示

1. **分类分场景选"即播 or 详情"**：短视频/AV = 即点即播 + 上下滑；电影/剧集 = 详情优先。一个 App 里两种范式并存是完全可以的，关键是**按内容类型给默认行为**。
2. **上下滑切视频在"播放列表上下文"里很有用**：比如"同演员的全部作品"或"某个系列"，全屏播放时上下滑切下一个，比退回列表再点快得多。这是演员体系的天然加成场景。
3. **迷你播放器是我们最该抄的**：找片场景下"先试看再决定"，返回列表时小窗保持播放，体验远超"退出即停止"。本地流播放无 DRM，可进一步做系统级 PiP。
4. **进度记忆 = 刚性需求**：本地片库用户经常中断观看（尤其长电影/剧集），全局续播 + 每条目进度条必须做；局域网场景还可记录"看过的设备/断点时间"。
5. **播放页滚动式详情（Bilibili 模式）适合剧集/AV**：播放器在上、评论区/简介/相关在下的滚动单页，比"播放器页面 + 详情页"两个页面少一次切换。可作为详情页的补充形态（尤其移动端竖屏场景）。

## 3. Jellyfin / Emby / Infuse / VidHub：自建媒体库 App 的成熟答案

### 3.1 它们怎么做的

**点开即播 or 详情优先？—— 主流是"详情优先，但播放触达极短"**
- Jellyfin/Emby/VidHub：点封面进**详情页**（大图 + 简介 + 评分 + 元数据 + 播放按钮 + 集列表 + 演员）。详情页顶部是巨大的 **"播放 / 从上次继续" 主按钮**，一条路径进播放。
- Infuse：点封面进详情，详情页大播放键；但**详情页支持左右滑动切换相邻条目**（把"浏览"和"播放"连起来）。
- 结论：自建库产品没有走"点封面即播"，因为**元数据是自建库的核心价值**（刮削来的海报/简介/评分不该被跳过）；但它们都把"播放"做成详情页的一键动作，不设多余确认。

**剧集管理**
- 结构：**剧集条目 → 季 → 集** 两级导航，详情页内嵌"季选择 + 集列表"；集列表每行显示集名、时长、**该集是否看过/进度**（Jellyfin 有 watched 标记和进度条）。
- 播放后返回列表，该集自动标记看过/进度；详情页主按钮变为「播放下一集（从上次）」。
- 多版本文件（同一集有多个文件/分辨率）在详情页选择。

**演员/导演页**
- 详情页有**演员头像横排**（点击进人）；**演员页 = 头像 + 简介 + 该演员全部作品**（按年份/类型排序，作品也是封面墙）。
- Jellyfin 的 People 支持关联到外部资料（TMDB），本地库则以刮削数据为准。
- 这是自建库与"流媒体目录"不同的地方：**本地库的演员数据是用户自己的资产**，可以做聚合、做筛选。

**元数据展示**
- 自建库详情页特别强调**文件规格**：分辨率（1080p/4K/HDR）、编码（H.264/HEVC/AV1）、音频格式（DTS/TrueHD/Atmos）、码率、文件大小、音轨/字幕轨列表。
- 对发烧友这是"值不值下/值不值看"的决策信息，流媒体产品不会展示这些。

**续播逻辑**
- 全局「继续观看」行（Continue Watching / Up Next）：按**条目维度**记进度；剧集记到"集"，电影记到"秒"。
- 进度存在**服务端**（Jellyfin/Emby），跨设备同步；客户端只上报"位置 + 是否看完"。
- 完成度阈值（如 >90% 视为看完）避免"差 1 分钟没看完就永远在继续观看里"。

**移动端导航**
- 现代自建库 App（Jellyfin 移动端、VidHub、Infuse 主界面）普遍用**底部 Tab**（首页/媒体库/搜索/设置，4~5 个）；老式/桌面移植版用**左侧抽屉**，移动端体验明显差一截。
- 媒体库入口常按**媒体类型**分（电影/剧集/音乐/照片），或按**文件夹/收藏夹**（Infuse 的 Library/Favorites/Up Next）。

### 3.2 为什么合理

- **详情优先**：自建库的元数据（海报、简介、规格、演员）是花钱/花时间刮削来的资产，详情页是它的展示舞台；同时"播放"是一键动作，不牺牲效率。
- **季-集两级**：与剧集文件结构天然匹配，层级不过深（条目→季→集→播放，最多 3 跳）。
- **演员页**：自建库没有平台推荐算法，**演员/导演页就是它最强的"发现"引擎**——从一部片跳到演员再跳到演员的其他片，是本地库最自然的导航。
- **服务端记进度**：多设备（手机/电视/PC）共用一份进度，是自建库相对"单机播放器"的核心差异点。
- **底部 Tab**：拇指可达、当前所在位置可见；抽屉在移动端是折叠菜单，层级感差且多一次点击。

### 3.3 对我们自建媒体库的启示

1. **移动端骨架直接抄 Jellyfin/Infuse**：底部 Tab + 首页（继续观看 + 分类行）+ 详情页信息中枢 + 全局搜索。这是经过验证的"媒体库移动端"范式，不需要发明。
2. **详情页是我们的信息中枢，且比它们更重**：除通用元数据外，我们的 AV 内容有"演员/系列/标签"三维信息，详情页要能承载"演员多人横排 + 标签墙 + 同系列作品"。
3. **演员页 = 我们的杀手锏**：做成"演员个人主页"：大头像 + 简介 + 按分类聚合的作品墙 + 相关演员；从任何详情页的演员头像 1 跳进入。演员体系的价值只有在移动端 1~2 跳可达时才成立，**导航深度是红线**。
4. **季-集模型扩展**：电视剧用季-集；AV 的"系列（series）/ 分集"也可套同一模型（如系列=季、多部曲=集），保证一套组件两用。
5. **进度存储放服务端**：我们是局域网 + 自建后端，天然适合服务端统一记进度，三端同步；比 Jellyfin 还简单（不需要账号体系，本机/局域网即可）。
6. **文件规格展示**：移动端详情页要展示但**默认折叠**（发烧友会点开，普通用户不被干扰）。

## 4. 短视频 App（抖音/TikTok）：沉浸手势，可借鉴的"播放器内手势语言"

### 4.1 它们怎么做的

- **竖屏全屏沉浸**：9:16 内容铺满全屏，无边框无卡片，一切 UI 都是悬浮层。
- **上滑下一个 / 下滑上一个**：核心手势，无限 feed，切换即加载（预加载下一两个，切换零等待）。
- **双击点赞**：屏幕中央双击 = 点赞 + 红心动画；是"沉浸时不打扰"的轻互动。
- **右侧竖排操作列**：点赞/评论/分享/收藏按钮贴着屏幕右缘（**单手拇指热区**），左侧留给手势区。
- **长按**：暂停并呼出菜单（倍速/不感兴趣）；**单击**：暂停/播放。
- **评论区半屏弹层**：左滑或点评论图标弹出，当前视频**不中断**，关闭后回到原位置。
- **进度条**：极简细横条在底部，可拖动；全屏时几乎不可见。
- **预加载**：上下滑动近乎瞬时出片，靠预加载下一个/上一个的内容。

### 4.2 为什么合理

- **零决策消费**：内容短、量大，"浏览"就是"播放"；沉浸 + 手势化把操作 UI 降到最少，内容面积最大化。
- **手势与热区分离**：屏幕中央做手势（滑/双击/长按），屏幕边缘做按钮（拇指自然够到），互不打架。
- **预加载**：切换的"即时感"是短视频体验的第一要素，宁可浪费流量也不可等待——**这是"内容近在咫尺"的心理模型**。

### 4.3 对我们自建媒体库的启示（本项目短视频非主战场，但手势可借鉴）

1. **全屏播放器的"沉浸层"应学 TikTok**：播放中隐藏一切 chrome（隐藏到只剩进度条），单击唤出控制栏，双击左右快进，长按呼出菜单（倍速/标记/加入片单）。
2. **双击点赞 → 映射为"标记/收藏/好评"**：本地库没有平台点赞，但「双击标记收藏」或「双击加入片单」是顺手且不打断播放的轻操作。
3. **上下滑切换在 AV/演员作品列表里直接复用**：进入"某演员作品"全屏播放后，上下滑切下一个作品 = 我们最爽的手势。
4. **预加载思想**：局域网带宽充足，播放器可在当前视频即将结束时预加载下一个（同列表上下文），实现接近零等待的连播。
5. **竖屏内容处理**：若 AV/短视频有竖屏素材，播放器容器应自适应（9:16 撑满 or 居中黑边），而不是强制拉伸。

## 5. 移动端通用规范（跨品类底层规则）

### 5.1 底部导航 vs 抽屉
- **底部 Tab**：3~5 个一级入口，拇指可达、位置恒定、可见即所得。适合"首页/媒体库/搜索/演员/我的"这类高频一级导航。
- **抽屉**：内容多、层级深时省空间，但**入口被隐藏**、需要一次滑动才能看到，移动端只适合"设置/更多"这类低频入口。
- 结论：**主导航用底部 Tab（≤5 个），次级/低频用列表页或抽屉**；不要在底部堆 6 个以上。

### 5.2 返回手势与返回栈
- iOS：右滑边缘返回（系统级）；Android：返回键/手势。**自定义页面不要做"返回手势与系统手势冲突"的设计**（如播放器内把右滑映射成快进，会与 iOS 返回冲突）。
- 返回栈原则：**返回 = 沿进入路径逐级回退**；播放器一般是模态层——返回时先退全屏 → 再回到进入页；若播放仍在继续，应收缩为 mini player 而不是停止播放。
- 深坑：返回后页面状态丢失（列表滚回顶部/详情重载）。移动端必须**保留列表滚动位置与详情页状态**。

### 5.3 横竖屏切换
- 浏览/详情/书架：**锁定竖屏**（不随传感器旋转，避免误转跳页）。
- 播放器：**横竖都支持**，跟随传感器或手动切换；切换动画平滑、播放不中断、进度不丢。
- 横屏播放中转为竖屏：主流做法是**退到半屏/小窗继续播**（YouTube）或保持竖屏全屏（短视频类）；不要"强制横屏播放不允许转竖屏"。
- 锁屏方向开关（iOS 旋转锁定）时，播放器应有"强制横屏"按钮作为出口。

### 5.4 触控热区
- 最小热区 **44×44pt（iOS）/ 48dp（Android）**；相邻按钮间距 ≥8pt 防误触。
- **高频操作放右侧/拇指弧区**：播放器内快进快退靠双击两侧；点赞/下一集/倍速等放右侧竖排；左侧留给"返回/更多"。
- 播放器控制栏布局要有"上（标题/返回）、中（进度条）、下（控制按钮）"的稳定心智模型。

### 5.5 列表 vs 网格
- **网格**：封面驱动的浏览（电影墙、AV 墙、演员头像墙、搜索结果），信息密度高、扫视快；卡片比例统一（2:3 竖版或 4:3 横版）。
- **列表**：信息密度高于封面的场景（剧集集列表、继续观看带进度、历史记录、搜索建议、多文件版本选择）。
- 可提供"网格密度/列表切换"（Infuse/Jellyfin 都有），默认按内容类型定。

### 5.6 播放器控制栏自动隐藏
- 播放中 **3~5 秒无操作自动隐藏**全部控制层；单击唤起；唤起后无操作再隐藏。
- 隐藏后保留最小信息：进度条（细线）+ 可选时间码；标题在切换/唤起时显示。
- 控制栏分三区：顶部（返回/标题/投屏/更多）、中部（进度+时间）、底部（播放/快进/倍速/下一集/锁）。
- 播放器内不要常驻任何按钮——这是"沉浸感"的底线。

### 5.7 亮屏 / 锁屏 / 后台控制
- **播放中保持屏幕常亮**（wakelock/screen awake），不随系统自动熄屏；暂停后可恢复系统亮度策略。
- **锁屏媒体控制**：锁屏/通知栏显示封面 + 播放/暂停 + 上/下一段（或上一集/下一集）+ 进度条；用系统 MediaSession（Android）/ Now Playing（iOS）。
- **蓝牙/有线耳机媒体键**：播放/暂停/下一首必须响应（MediaSession 天然支持）。
- **画中画（PiP）**：支持系统 PiP 时，切后台自动变小窗；本地/自建内容无 DRM 限制，PiP 全功能可用。
- **后台播放策略**：视频类默认后台暂停（或 PiP），音频类（音乐/播客）后台继续——AV/短视频默认不后台续播，避免尴尬/耗电（可设"仅音频模式"）。

## 6. 面向「本地 AV 片库 + 演员体系 + 局域网 HTTP 流播放」的特化设计

### 6.1 AV 子域：封面即决策
- **高密度封面网格是 AV 的主入口**：2 列（手机）~3 列大图网格、缩略图即"试看"（可加：长按出 3~5 帧预览动图）；排序按"最近添加/热度（本地播放次数）/演员/系列"。
- **点封面默认即播**（或"点封面 = 播放、长按 = 详情"）；播放中**自动连播下一个**（默认开，符合"连续看"行为，但给"不自动连播"开关）。
- **隐私是一等公民**：无痕模式（不记进度/不记历史/不留最近观看）、隐藏最近观看、应用锁（FaceID/密码）、退出自动清除记录——这些在 AV 场景不是"额外功能"而是**上线前提**。
- **防误触**：播放中屏幕长亮时防误触锁（锁定后任何触摸仅唤出解锁按钮）；连播切换前给 5 秒倒计时可取消（避免自动跳错）。
- 分级/过滤：按演员、系列、分类、标签多维筛选；"只看未看/只看收藏"。

### 6.2 演员体系：从"元数据字段"升级为"一级导航"
- **演员卡**：头像/剧照 + 名字，圆形或竖卡；出现在详情页横排、搜索建议、首页 row。
- **演员主页**（1 跳可达）：大头像 + 简介 + 统计（作品数/累计时长）+ **按分类分组的作品墙** + 同一演员的不同时期筛选。
- 关系链：详情页 → 演员页 → 另一部作品 → 另一演员，形成本地"看片图谱"；这要求**所有详情页的演员头像都可点击**。
- 数据来源：本地元数据（nfo/刮削）+ 手动关联；不依赖在线服务也能用（离线优先）。

### 6.3 局域网 HTTP 流播放的交互含义
- **没有自适应码率**（非 HLS/DASH）：进度条拖动 = 服务端 Range 请求 + 播放器 seek 到**关键帧**；交互上要预生成**关键帧索引**，让 seek 预览条秒级响应（否则拖一下缓冲 3 秒是最大挫败点）。
- **封面/缩略图/关键帧离线生成**：海报、缩略图、演员头像、seek 预览帧全部本地预生成，列表滚动不卡、不耗局域网带宽。
- **缓冲策略**：局域网带宽通常不是瓶颈，但播放器 UI 仍要正确处理 loading/错误/断线（服务端重启、设备休眠、Wi-Fi 切换），**断线自动重连 + 从断点续播**是本地播放的可靠性质检。
- **无 DRM 红利**：PiP、后台音频、锁屏控制、多音轨/字幕自由切换都可用——这些是本地库相比流媒体 App 的体验优势，要在交互上体现出来。
- **多设备**：手机 A 看到一半，电视/PC 接着看：进度存在自建后端，详情页主按钮直接显示"从上次继续（X 设备，剩余 Y 分钟）"。

## 7. 移动优先的视频模块交互设计建议清单（可直接落地）

> 约定：P0 = 首版必须，P1 = 首版尽量，P2 = 二期。标注的数值可直接作为产品需求写入。

### 7.1 书架（首页 / 媒体库）
1. **底部 Tab 首页 = "继续观看 + 内容墙"**（P0）。布局从上到下：顶部栏（应用名/搜索/设置）→ 继续观看行（横滑，卡片带进度条，点击续播，可"×"移除）→ 分类行（电影/剧集/短视频/AV 各一行，按内容类型给默认排序：最近添加、未看优先）→ 演员行（圆形头像横滑）。
2. **滚动时隐藏顶部栏**（P0 可选：首版可做常驻，二期再做隐藏）。
3. **网格密度切换**（P1）：AV/电影默认 3 列大图网格，提供"列表视图"开关（列表显示进度/规格信息）。
4. **空态引导**（P0）：首次打开无内容时给"导入文件夹/扫描局域网服务器"大按钮 + 图文说明，不要给空白页。
5. **下拉刷新**（P1）：本地库变动后手动刷新；有后端时用 WebSocket 推送"库已更新"提示。

### 7.2 详情页
1. **统一详情模板**（P0）：顶部大图背景（渐变压暗）→ 标题 → 主操作区（**「播放 / 从上次继续（xx:xx）」大按钮 + 次要按钮：加入片单/下载/标记看过**）→ 规格标签行（分辨率/HDR/音频格式/时长，默认折叠二级）→ 简介（超过 3 行"展开"）→ 演员横排（头像可点）→ 相关推荐（同演员/同系列/同类型）。
2. **剧集详情**（P0）：季选择（下拉/横向 tab）→ 集列表（每行：集号+标题+时长+该集进度条+看过标记）；主按钮显示「播放下一集」。
3. **AV 详情特化**（P0）：点封面**直接进播放**，详情是次要路径（封面角标"ⓘ"或长按进入）；详情页主按钮 =「播放」；提供「系列」关联卡片。
4. **详情页左右滑动切相邻条目**（P2，抄 Infuse）：浏览连续条目时少一次返回。
5. **演员页**（P0）：从任意详情页演员头像 1 跳进入；页内 = 大头像 + 简介 + 作品统计 + 分类分组作品墙 + 相关演员；作品墙点封面即播（AV 默认）/进详情（电影剧集默认）。

### 7.3 播放器
1. **全屏沉浸 + 控制栏 3 秒自动隐藏**（P0）：单击唤出，再单击暂停；隐藏后仅留细进度条。
2. **手势**（P0）：
   - 双击屏幕左 1/3 = 快退 10s，右 1/3 = 快进 10s（有轻微震动反馈 + 时间角标）。
   - 单击中央 = 播放/暂停。
   - 长按 = 呼出菜单（倍速 0.5×~2×、标记、加入片单）。
   - 亮度/音量：屏幕左缘上下滑 = 亮度，右缘上下滑 = 音量（P1）。
   - **上下滑切换**（P0，在"列表上下文"内有效）：进入播放时记录上下文（演员作品/系列/季/类型/播放列表），全屏时上滑下一个、下滑上一个，顶部显示"下一个：xxx"提示；无上下文时禁用。
3. **进度条 seek 预览**（P1）：拖动时显示关键帧缩略图 + 时间；基于本地预生成的关键帧索引，局域网内应做到"拖动即响应"。
4. **剧集连播**（P0）：本集结束 → 8~10 秒倒计时「下一集」，可点跳过/取消；「跳过片头」按钮（片头时长本地记忆，同一剧集自动应用）。
5. **AV 自动连播**（P0）：默认播完自动播下一个（同列表上下文），**倒计时 5 秒可取消**；提供"不自动连播"全局开关。
6. **播放结束**（P0）：电影/单集播完 → 回到详情页并标记看完，可显示"相关推荐"；剧集 → 自动连播下一集。
7. **播放器退出**（P0）：从播放器返回 = **收缩为 mini player**，不停止播放；播放器内提供"关闭"（停止并移除）按钮。

### 7.4 返回栈与迷你播放器
1. **返回栈规则**（P0）：全屏播放是**模态层**——返回键先退全屏（回到半屏/竖屏播放或详情页），播放不中断；再返回 = 播放收缩为 mini player；连续返回 = 沿进入路径逐级退，**列表滚动位置保留**。
2. **mini player**（P0）：右下角悬浮卡（缩略图 + 标题 + 进度 + 播放/暂停 + 关闭），可拖动到角落，点击回全屏；**全局存在**（在任何页面之上），提供"收起成音频条"或"关闭"。
3. **系统 PiP**（P1）：iOS/Android 支持时，切后台自动进系统画中画；本地内容无 DRM 限制，直接可用。
4. **状态保留**（P0）：返回后详情页/列表状态不重载（View 栈 + 滚动位置缓存），这是移动端"不廉价"的细节。

### 7.5 续播
1. **全局「继续观看」行**（P0）：置顶于首页；卡片 = 封面 + 底部进度条 + "剩余 xx:xx"；点击直接续播。
2. **进度存储**（P0）：粒度 = 电影/单集到"秒"，剧集到"集"；**存服务端**（自建后端），三端同步；>95% 视为看完并移出继续观看（保留在历史记录）。
3. **详情页主按钮三态**（P0）：未看 =「播放」；看一半 =「从上次继续（剩余 xx:xx）」+ 可"从头播放"；看完 =「重播」。
4. **历史记录页**（P1）：按时间倒序，显示进度，可清除全部/单条（AV 场景配合无痕）。

### 7.6 连播
1. **播放列表上下文**（P0）：进入播放时固化上下文 = 当前列表（同演员作品/同系列/季内顺序/类型/手动片单），作为连播队列与上下滑切换的依据；队列可在播放器内查看/跳转/移除。
2. **剧集连播**：见 7.3.4；**电影不自动连播**（播完回详情）。
3. **队列 UI**（P1）：播放器内"列表"图标打开当前队列（横向可滑动），显示"下一个"及进度。

### 7.7 手势
1. **手势分层防冲突**（P0）：播放器内手势与系统手势冲突表——iOS 右滑边缘返回在**全屏播放时会被播放器接管**（全屏无返回手势，用顶部返回按钮/系统返回），半屏/普通页面一律交给系统；**Android 返回键永远保留**。
2. **双击/单击/长按/滑动** 四种手势的优先级明确（单击 < 双击 < 长按，用时间窗区分；滑动区分方向与起点区域）。
3. **防误触**（P1）：播放中屏幕常亮且无操作时，提供"锁屏"按钮；锁定后任何触摸只唤出解锁按钮（AV 场景尤其需要）。
4. **触感反馈**（P1）：快进/快退/点赞/切换视频给轻微 Haptic；连播倒计时给提示音或震动（可选）。

### 7.8 导航
1. **底部 Tab（4 个）**（P0）：媒体库（首页）｜ 搜索 ｜ 演员 ｜ 我的（观看历史/片单/设置）。≤5 个，不堆砌；"短视频"作为媒体库内的分类入口而非独立 Tab。
2. **全局搜索**（P0）：可搜 片名/演员/导演/标签/系列；结果按"演员 / 电影 / 剧集 / AV"分组展示（演员匹配置顶）；支持拼音/首字母（本地库中文场景）与模糊匹配。
3. **演员体系导航**（P0）：演员 Tab = 演员墙（按热度/最近添加/首字母）；详情页演员头像 → 演员主页 → 作品墙，全程 1 跳；这是本项目区别于通用媒体库的体验王牌。
4. **类型/分类切换**（P0）：媒体库页顶部分类横滑 tab（电影/剧集/短视频/AV），AV 内部再分（分类/系列/演员/标签/收藏）。

### 7.9 横竖屏
1. **浏览/详情锁定竖屏**（P0）；**播放器支持横竖旋转**（P0），旋转动画平滑、播放与进度不中断。
2. **全屏播放的进入策略**（P0）：点播放默认**横屏全屏**（电影/剧集）；竖屏内容（短视频/竖屏 AV）默认竖屏全屏；系统旋转锁定时提供"强制横屏"按钮。
3. **横屏 → 竖屏转换**（P1）：横屏播放中转竖屏 = 退到 mini player / 半屏继续播（YouTube 式），不强制保持横屏。

### 7.10 亮屏 / 锁屏 / 后台
1. **播放中保持屏幕常亮**（P0）；暂停后恢复系统策略。
2. **系统媒体控制（MediaSession / Now Playing）**（P0）：锁屏/通知栏 = 封面 + 播放/暂停 + 进度 + 上一集/下一集；蓝牙耳机媒体键可用。
3. **PiP / 后台**（P1）：切后台默认 PiP；提供"后台继续播放（仅音频）"开关，**AV 默认关闭**（隐私/耗电），音乐/播客类默认开。
4. **来电/插拔耳机**（P0）：自动暂停，恢复后不自动播放（防尴尬）。

### 7.11 局域网流播放的技术交互点
1. **seek 优化**（P0）：服务端支持 Range；客户端 seek 对齐关键帧；**预生成关键帧索引**供进度条预览，目标 = 拖动后 <300ms 出画面（局域网内）。
2. **列表性能**（P0）：封面/缩略图/演员头像**本地预生成并缓存**（按文件 hash 缓存），滚动不闪白；Web 端用懒加载 + 骨架屏。
3. **断线恢复**（P1）：播放中服务端不可达 → 明确错误态（"无法连接媒体服务器"）+ 重试；恢复后**从断点续播**。
4. **多音轨/字幕**（P1）：播放器内一键切换音轨/字幕（本地 mkv 常见多轨，是 Infuse 用户的刚需，做成播放器一级操作）。
5. **播放记录上报**（P0）：播放中每 5~10 秒或暂停/退出时上报进度到后端（节流，避免每帧请求）。
