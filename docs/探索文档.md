## 2. 数据与存储

- **主数据库**：`%APPDATA%\com.lzy.leisure\leisure.db`（SQLite，bundled）。
  - 表 `comics`（1441 行）：`type` = folder（图片目录）/ archive（zip/cbz）/ pdf / series（子系列或容器）；`is_container`=1 为容器卡（书架不显示）；`series_id` 指向所属系列；`reading_progress` 为章内 0-based 页索引。
  - 表 `meta`（schema_version=4、web_password 等）、`root_dirs`、`videos`、`storyclub_issues` 等。
- **封面/配置库**：**漫画封面不在 appdata**——在**每个漫画本体目录下的 `.leisure-covers.db`**（`%APPDATA%` 的 covers 目录只存小说/视频封面）。每个本体库一张表结构：
  - `covers(path, data, mime, width, height, created_at)`：封面 BLOB，`path` = 记录相对本体目录的路径（本体自身为 `''`，章节为 `'1'`、`'2'`…）。
  - `configs(path, key, value)`：**手动封面参数**（`cover_crop_offset`=裁剪偏移、`cover_crop_y`、`cover_from_offset`=已按偏移生成标记）+ **阅读进度 `scroll_pct`**。configs 是用户数据，**清理/扫描从不删 configs**。
  - `page_indices` / `previews`：封面裁剪用的页面条带索引与预览图缓存（可再生成）。
- **漫画根目录（示例结构）**：`D:\漫画`（容器「漫画」→ 子系列如 妖神记[283章] / 生存日[18章]）；`D:\漫画\《神奇漫画》`（容器 → 多个子系列）。书架顶层 = 容器下的各子系列卡（`load_top_level_comics` 排除 is_container）。
- **章节排序**：`load_chapters` 用系列目录 `index.json` 覆盖标题与顺序（`title_map`/`order_map`），无 index.json 时按 title 自然排序。
- **HTTP/局域网**：`get_web_urls` 命令取地址；`http_dispatch.rs` 里有与桌面命令同名的 HTTP 接口。

## 2.1 封面系统（重点：读库优先，绝不被扫描重置）- **归属/键控**（`covers_db.rs`）：`bucket_dir(comic)` = 漫画「本体目录」（series 且父为容器→自身；章节→沿 series_id 递归到本体）；`rel_key_of` = 绝对路径减去本体目录。键只随目录内部结构变化，**移动根目录不失效**；封面跟着漫画目录走。
- **读取**（`covers.rs::get_cover`）：① `.leisure-covers.db` 命中即返回 → ② `cover.*` 文件 → ③ 第一页 → ④ series 回退第一章。命中后**绝不覆盖**。
- **手动封面**：`set_comic_cover_from_offset`（前端「选封面」）从页面条带按 `cover_crop_offset` 裁剪生成 jpeg 封面 + 写 configs（offset + `cover_from_offset=1` 标记）。`upload_comic_cover`（PDF）上传 data URL。
- **恢复手动封面**（2026-09-06 新增）：`get_cover` 发现该 key 有 `cover_crop_offset` 但库里还是旧默认图（如迁移导入的 webp）或封面缺失时，**用保存的 offset 重新生成手动封面并写回**（一次性，用 `cover_from_offset` 标记避免重复重建），绝不回退成默认第一页。
- **扫描/增删根不影响封面**：`remove_root_dir` 只删 leisure.db 记录、不碰 `.leisure-covers.db`；重扫后 id 稳定（路径 hash）、键不变 → 封面直接复用。
- **⚠️ 已修的 bug（2026-09-06）**：
  1. `purge_after_scan` 原用**扫描切片**计算有效键集，切片缺父记录（如单章重扫）时 `bucket_of` 失败 → 该章被排除 → `purge_missing` **误删仍在的封面**。改为**基于全量 comics 表**计算有效集：只有真正从库中消失的章节才清理。
  2. `purge_missing` 现在对**有手动 configs 的封面一律不删**（宁可残留也不误删，与 configs 保护策略一致）。
  3. `reset_comic_cover`（恢复默认）现在同时清除 `cover_crop_offset`/`cover_crop_y`/`cover_from_offset`，避免残留 offset 又把手动封面反推回来。
- **迁移来源**：`.leisure-covers.db` 里的 `image/webp` 封面是 `scripts/migrate_from_mangashelf.py` 从旧 MangaShelf 导入的（旧库 standard 封面 + `cover_crop_offset` 手动参数）；8/2 同秒批量写入的就是迁移产物。app 内新设置的是 jpeg。
- **调试入口**：可直接用 Python/sqlite3 读 `D:\漫画\...\.leisure-covers.db` 验证键与封面；`load_configs` 里 `scroll_pct` 是阅读进度（**别误当封面参数删**）。

## 2.2 跨标签页同步（浏览器多开）

- 框架 `useData`（app-kit/shared/ui/src/data/useData.ts）对每个 localStorage 键挂 `storage` 事件做**跨标签页同步**：一个页面改值，其他同源页面跟着变。
- **导航/视图类状态**（`module-tab` 顶层模块、`video-tab` 视频内标签）若同步，浏览器开两个页签会互相抢视图（一个切到视频、另一个跟着跳）。已在声明里给这类键设 **`syncCrossTab: false`**，各标签页独立。
- 实现：`FrontendItemDef`/`DataKeyRef` 新增 `syncCrossTab?: boolean`（默认 true）；`useData` 在 `syncCrossTab===false` 时不注册 storage 监听。**这是 app-kit 框架层改动**，改框架后下游项目需重跑 `npm install`（file: 副本）生效。
- 认证类键（如 `web-token`）保持默认同步，保证多标签页都处于登录态。

## 4. 漫画阅读器架构（重点：无痕拼接）

文件：`src/components/comic/ReaderView.tsx`

### 4.1 组件层级

- `ReaderView`：管理当前章 `chapter` 状态 + 系列章节列表 `chapters`；`chapterIdx = chapters.findIndex(id)`；`pdf` 类型 → `PdfReader`，其余 → `ImageReader`（`key=chapter.id`，切章即重挂载，状态全清）。
- `ImageReader`：外层只持有「无痕」开关与滚轮步长（localStorage 经 `data.ts` 的 `store.keys["reader-seamless"]` / `["reader-scroll-step"]` 持久化）。
- `ImageReaderInner`：核心。
  - **拼接队列** `queue: QueuedChapter[]`，`QueuedChapter = { comic, pages, pageOffset }`，`pageOffset` = 该章第一页在整条 DOM 里的全局页索引。
  - `queueRef` 同步镜像（setState 前先改 ref，异步逻辑都读 ref）。
  - `SEAMLESS_TRIGGER = 1600`：滚动距底/顶 1600px 内提前拼下一/上一章。
  - `chapterIdxRef` = 当前所在章在 queue 内的索引；`loIdxRef` = 队首章在 `chapters` 里的索引（prepend 后-1，关闭开关时复位；懒初始化：null 时取当前 `chapterIdx`，避免 chapters 晚到时钉死为 -1）。
  - `appendNext`：从队尾章之后找下一个可拼接章（folder/archive）接入；**跳过空章（0 页）**；遇到 pdf/series 边界或到末尾 → `noMore=true`（显示「已到末尾」）。
  - `prependPrev`：把上一章插到队头，所有 `pageOffset` 后移 shift，`prependPendingRef` 记录滚动修正（useLayoutEffect 里 `scrollTop += scrollHeight 差`），保持视口内容不动。
  - `maybeAppend`/`maybePrepend`：在 `handleScroll`、章节列表加载完成、恢复位置后、开关切换时调用。
  - 进度：`handleScroll` 定位当前章，跨章向下时把上一章标记读完（`setReadingProgress(old.id, old.pages.length)`）；章内进度用高度比（单章）或 `chapterProgressPct`（多章）；`scheduleSave` 500ms 防抖写 `setReadingProgress` + `setComicConfig({scroll_pct})`。
  - 恢复：优先 `scroll_pct`（config）按百分比定位，其次 `reading_progress` 页码；用户滚动后不再强改位置。
  - 页面懒加载：`ReaderPage` 用 IntersectionObserver（rootMargin 800px）按需 `getPageDataUrl`，模块级 `pageCache` 缓存 data URL。

### 4.2 ⚠️ 已修复的竞态 bug（勿回退）

**症状**：部分章节（大章/慢盘更明显）到章末无痕不接下一章、显示「已到末尾」，重开才恢复。
**根因**：打开章节时 `getChapters`（章节列表）与 `listPages`+`getComicConfig`（本章页面）并发；列表先返回而拼接队列仍为空时，旧 `appendNext` 执行 `q[q.length-1]` → `undefined.pageOffset` 抛异常 → catch 把 `noMoreRef` 永久钉死 true。
**修复要点（2026-09-06）**：
1. `appendNext` / `prependPrev` 在队列为空时直接返回（等加载完成由 effect/滚动重试），不再崩溃。
2. `lo < 0`（当前章不在列表）时不再盲目接到 `chapters[0]`。
3. 下一章 0 页时向后跳过继续找；单次 `listPages` 失败不再置 noMore（下次滚动重试）。
4. 关闭「无痕」时无条件复位 `noMore`/`noMorePrev`，再次开启能重新尝试（旧代码在队列只有一章时跳过复位，一旦坏掉开关也救不回）。
**验证**：`node scripts/sim-seamless-race.mjs`（旧实现竞态后 noMore=true / 新实现 noMore=false，且空章跳过、pdf 边界正确）。

### 4.3 边界与设计约束

- pdf / series 类型章是**拼接边界**：不能把 PDF 页塞进图片滚动条（pdf 章走 PdfReader），遇到即 `noMore`。
- 无痕只对 folder/archive 生效；`nextIdx` 由 `loIdxRef ?? chapterIdx + queue.length` 推算，prepend 后靠 `loIdxRef` 保持正确。
- 端标记渲染：`(seamless ? noMore : totalPages > 0)`。
